# Local development

Use the root README startup sequence. The repository itself is the `omnimcp` monorepo root; no additional nested checkout is required. On Windows PowerShell with execution policy restrictions, invoke `pnpm.cmd`, `npm.cmd`, or `node_modules/.bin/pnpm.cmd`.

## Environment

| Variable                                                    | Required               | Purpose                                                                              |
| ----------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------ |
| `DATABASE_URL`                                              | Gateway                | Backend PostgreSQL login; can assume `omnimcp_gateway`                               |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`                         | Gateway/seed           | Supabase Auth verification                                                           |
| `SUPABASE_SERVICE_ROLE_KEY`                                 | Seed only              | Creates local seed account; never sent to browser                                    |
| `MASTER_KEY`                                                | Gateway/seed           | Base64-encoded random 32-byte AES-GCM key                                            |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Web build              | Public Auth client settings                                                          |
| `NEXT_PUBLIC_GATEWAY_URL`                                   | Web build              | Gateway origin; defaults to localhost:4000                                           |
| `WEB_ORIGIN`                                                | Gateway                | Single allowed browser origin including scheme/port                                  |
| `GATEWAY_HOSTS`                                             | Gateway                | Allowed Host names without ports; configure public hostname for deployment           |
| `PORT`                                                      | Optional               | Gateway listener, default 4000                                                       |
| `CONNECTOR_PRIVATE_HOSTS`                                   | Optional               | Exact deployment-approved private destinations; empty by default                     |
| `CONNECTOR_INSECURE_PG_HOSTS`                               | Local development only | Exact PostgreSQL hosts allowed without TLS, also requiring private-host allowlisting |
| `CONNECTOR_MODULES`                                         | Optional               | Comma-separated installed ES module URLs exporting a connector                       |
| `WORKER_CONCURRENCY`, `WORKER_TIMEOUT_MS`                   | Optional               | Defaults 4 / 30000; max 16 processes and 30 seconds                                  |
| `OAUTH_PROVIDER_MODULES`, `OAUTH_REDIRECT_BASE`             | Optional               | Deployment-owned provider adapters and registered public Gateway callback origin     |
| `SEED_EMAIL`, `SEED_PASSWORD`                               | Seed                   | Local account; generated password is unique to checkout                              |
| `LLM_CHAT_URL`, `LLM_MODEL`, `LLM_API_KEY`                  | Optional               | Compatible chat-completions API used only to propose Playground arguments            |

`env:local` creates the two loopback network exceptions needed to test the local PostgreSQL connector. These are deployment configuration, never user-editable connection settings. HTTPS remains mandatory for HTTP connectors. Cloud metadata/link-local destinations remain blocked even with allowlisting.

## Trying each connector

1. **Demo CRM:** seed or create a connection, discover, select and publish the three tools. Search with `{}`. Note creation accepts `customerId` and `body` and normally waits for approval.
2. **OpenAPI:** provide an HTTPS API base URL, namespace, and an OpenAPI 3.0/3.1 URL, JSON/YAML upload, or pasted document. Supply a bearer token separately if needed. Discover, inspect operation risks, and select operations before publishing. The URL fetch does not follow redirects or external `$ref`s.
3. **PostgreSQL:** store a PostgreSQL URL in the secret field. Use **Select columns** to discover and choose schemas/tables/columns, save, then discover/publish generated READ tools. Configure the source database role as read-only. The local stack needs the loopback exceptions generated by `env:local`; hosted databases use certificate-verified TLS.
4. **Remote MCP:** configure the HTTPS MCP URL, namespace and independent upstream bearer token. Discover/publish selected tools. All upstream tools default to CRITICAL regardless of their untrusted annotations. Set explicit permissions before invocation. Programmatic configuration can set `protocol: auto` for SDK-supported legacy compatibility; modern is the default.
5. **Webhook:** set a random 32+ character signing secret and optional HTTPS outbound URL. The inbound endpoint is `/webhooks/<connection UUID>`. Send JSON with `x-omni-timestamp` (Unix seconds) and `x-omni-signature: sha256=<hex HMAC-SHA256(secret, timestamp + '.' + rawBody)>`. Events are encrypted and recorded; inbound delivery never executes an arbitrary tool.

## Commands

`pnpm dev:gateway` and `pnpm dev:web` run independently. `pnpm build` emits Node code under `dist/` and Next.js output under `apps/web/.next`. Start them with `pnpm start:gateway` and `pnpm --filter @omnimcp/web start`. `pnpm executions:reconcile` performs recovery bookkeeping only.

Fast tests need no Docker. Live/browser tests require local Supabase and the generated environment. Browser tests require both apps already running. They sign in to the real local Auth service; they do not intercept authentication or API responses. Live tests create isolated temporary tenants and PostgreSQL tables and clean up those fixtures without resetting seed data. The browser's normal tool calls remain in the seed organization's execution history.

`pnpm test:audit` starts its own Gateway on port 4100, uses disposable tenant/database fixtures, runs Inspector and local HTTPS REST/MCP upstreams, and writes load measurements to ignored `.local/audit-load.json`. Do not run it against production: it explicitly requires loopback Supabase and database addresses. The audit additionally needs OpenSSL to generate an ephemeral localhost TLS identity (available on Ubuntu CI and auto-detected in Git for Windows; otherwise set `AUDIT_OPENSSL`). Private test keys are generated in the OS temporary directory, cleaned up afterward and never committed. No external credentials or OAuth provider are needed.

Gateway spawns worker processes automatically in both development and production. There is no additional terminal or Docker broker to start. Apply additive migrations with `pnpm db:migrate` when upgrading an existing checkout; `pnpm db:reset` is the explicit destructive alternative.
