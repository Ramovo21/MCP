## Failures discovered and fixes

1. **Availability:** runtime connector handlers ran in Gateway; a synchronous hang or process crash could take down the API. Replaced runtime connector registry entries with private IPC proxies and bounded disposable processes, including management discovery/test operations.
2. **Permission bypass in discovery:** direct Supabase member policies exposed organization tool metadata without Gateway permission filtering. Removed those management/discovery policies; browser organization selection remains available.
3. **Credential reflection:** an upstream could echo a stored bearer token in an unexpected response field. Added recursive stored-value scrubbing before returning results, plus nested secret-in-config rejection.
4. **Ambiguous write semantics:** timeouts/crashes were reported as ordinary failures. Added explicit failure classes and `unknown` outcomes, durable worker claims, stable upstream execution IDs and regression coverage for writes followed by crashes.
5. **Migration command:** `db:migrate` reset all local data. It now applies additive migrations; reset requires the explicitly named `db:reset` command.
6. **Malformed request handling:** invalid JSON/body overflow returned generic 500 status. Gateway now returns 400/413 with sanitized errors.
7. **OAuth race during new implementation:** refresh needed a committed claim before contacting a rotating-token provider; callback needed a generation check against revocation. Added durable refresh states and authorization generations, with regression tests.
8. **Verification errors, not hidden:** Inspector's one-shot `--method server/discover` failed as unsupported. The supported modern CLI calls perform discovery internally; independent SDK negotiation is explicitly asserted. Initial new test-harness syntax/lint errors were repaired. The first complete audit run was 7/8 passing; subsequent full runs passed all eight groups.

## Remaining risks and production blockers

- **Trusted plugins only.** Workers share OS/filesystem identity and receive backend database connectivity. Process isolation protects availability, not hostile code or full native-memory exhaustion. Untrusted plugins need narrowed storage capabilities and container identities/network controls.
- **Infrastructure not deployed.** Provision TLS, exact origins/hosts, least-privilege backend database access, managed secrets/key rotation, backups/PITR and restore tests, production Auth/email policy, resource limits, reconciliation scheduling, monitoring and retention. Local private-network exceptions and test TLS keys must not be deployed.
- **Crash ambiguity remains.** No distributed queue/recovery worker or universal upstream idempotency. `unknown` effects and interrupted OAuth refreshes require reconciliation/reconnection. A host failure is outside the child-process crash test.
- **OAuth framework, not provider integrations.** Real provider registrations, credentials, scopes and external consent require deployment-specific adapters/verification. The generic adapter uses HTTPS and bounded SSRF-safe requests.
- **OpenTelemetry preparation only.** Trace context/events/exporter interface exists; no collector/exporter integration or telemetry backend was deployed/tested.
- **Load evidence is local.** No soak test, multi-replica test, production-scale database test, restore drill or external penetration test was performed. No performance optimization is claimed.
- Existing product limits remain: latest-100 lists/polling, restricted OpenAPI serialization, no arbitrary SQL/browser automation, no billing/enterprise SSO/invitation delivery. See deployment notes.

## Exact local startup

Prerequisites: Node >=22.19, pnpm 10.32.1, running Docker Desktop/Engine.

```sh
pnpm install --frozen-lockfile
pnpm db:start
pnpm env:local
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Dashboard: http://localhost:3000/dashboard. MCP: http://localhost:4000/mcp. Worker processes start automatically. Seed email is `developer@omnimcp.local`; the unique password is `SEED_PASSWORD` in ignored `.env`. `env:local` fills database/Auth/public frontend settings and generates `MASTER_KEY`; it preserves existing environment files. Optional worker/OAuth settings are documented in `.env.example` and `docs/local-development.md`.

Production-mode local run: `pnpm build`, then `pnpm start:gateway` and `pnpm --filter @omnimcp/web start` in separate terminals. Apply migrations before upgrading code. Full verification: `pnpm verify`, `pnpm test:live`, `pnpm test:audit`, `pnpm test:inspector:live`, and `pnpm test:e2e` with both apps running. Exact Inspector commands are in [mcp-verification.md](mcp-verification.md).
