## Failures found and corrected

1. The npm conformance `latest` release targets the old SDK. Pin official
   `0.2.0-alpha.11` for the modern revision and resolve its CLI via package metadata.
2. The fixture needed the official diagnostic tool, and MCP capability exceptions
   needed preservation as protocol errors instead of ordinary tool errors.
3. Cancellation was not passed to the execution dispatcher. It now uses the actual
   installed SDK `context.mcpReq.signal`, with a server-observed cancellation test.
4. SDK v2 `listTools()` auto-aggregates pages, bypassing the intended page boundary
   checks. Raw typed requests now enforce the connector's limits and cursor loop test.
5. Initial metadata validation overconstrained version strings and prevented an
   existing trusted audit connector (`version: '1'`) from loading. Accept bounded
   nonempty version identifiers, preserving backward compatibility.
6. The new example initially used the wrong management route and incorrect FK
   cleanup order. Corrected both, reran successfully and removed the failed run's
   temporary tenant without touching unrelated tenants.
7. ESLint rejected a control-character regex in the transcript writer. Use Node's
   `stripVTControlCharacters` instead.
8. Linux declaration build exposed inferred Express types that Windows compilation
   accepted. Explicit exported example interfaces fixed the Docker build.

Earlier failed runs are not reported as passes; the table refers to successful
reruns after fixes. Expected negative-path execution logs (`failed`, `denied`,
`unknown`) are assertions in passing security tests, not hidden suite failures.

## Security and execution behavior

Audit covers API and non-superuser Supabase RLS isolation of connections, tools,
executions, approvals and keys; revoked/cross-tenant keys; approval rejection and
approval races; secret encryption/redaction; SSRF/private destinations and
redirects; parameterized database access; malformed/oversized traffic; process
crash/timeout; upstream errors; and no automatic duplicate ambiguous WRITE.
New tests prove audit failure rolls back execution and custom auth/storage can be
injected without issuing Supabase/SQL calls in the execution unit fixture.

Existing audit load case: 40 READ calls, concurrency 8, 100% success, 0 failures,
mean 2395 ms, p95 3537 ms. Shared local development host; this is not a controlled
production benchmark or a performance guarantee.

## Remaining boundaries

- Default SaaS management, OAuth, rate limiting and worker durable claims remain
  PostgreSQL-based. Alternative stores need matching management/worker adapters.
  No Firebase/Auth0-specific production adapter or separately published npm
  distribution is shipped; workspace entry points support repository integration.
- Conformance runner is an explicitly pinned prerelease. Optional resources,
  prompts, tasks, sampling, progress and list-change workflows are not implemented.
- Connector output schemas are validated in the worker when supplied, but are
  not persisted/advertised in MCP yet. Discovery before execution adds read latency.
- Child processes isolate crashes, not malicious deployed code. Plugins retain
  worker OS/database privileges; deploy only reviewed modules.
- Upstream exactly-once effects require upstream durable idempotency. Cancellation
  and worker termination cannot undo completed remote writes.
- The example backend is intentionally disposable and in-memory. Its custom
  local bearer provider and HTTP allowlist are not production auth/network defaults.
- Google tests use local fixtures. No real Google account, public staging endpoint
  or external AI client was verified in this task.
- Next.js emits the existing optional ESLint-plugin warning; explicit ESLint and
  TypeScript gates pass. Docker's missing Git build metadata warning is nonblocking.
