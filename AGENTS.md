# OmniMCP architecture contract

OmniMCP is a multi-tenant integration gateway, not a chatbot. Use Node >=22.19, strict TypeScript, pnpm, Next.js, Supabase PostgreSQL/Auth/RLS, MCP spec 2026-07-28 and the official split v2 server/client packages. Inspect installed SDK APIs and official docs before transport changes. Streamable HTTP is the remote interface.

All user tool execution MUST go through gateway authentication, tenant resolution, registry lookup, permissions, policy, approval, durable claim, connector dispatch, execution tracing and audit. Never invoke connectors directly from browser or management routes. Discovery is tenant- and permission-filtered. Every query must be tenant scoped; test RLS as non-superuser. Never accept organization identity without verified membership or an organization-bound API key.

Connectors are plugins of connector-sdk, never core special cases. Browser automation is an extension interface only in V1. Namespaced tools require useful descriptions, JSON Schema and READ/WRITE/SENSITIVE/CRITICAL risk. Risk cannot be downgraded below connector baseline. CRITICAL always requires human approval; explicit permission is necessary for sensitive tools. Approval is bound to immutable arguments and principal, expires, and is atomically claimed. Do not promise exactly-once external side effects across a crash unless the upstream supports idempotency; never automatically retry ambiguous effects.

Encrypt credentials with authenticated encryption and tenant/connection associated data. Store API key hashes only. Do not log secrets, authorization headers or raw connector responses. SSRF checks must pin DNS addresses, restrict schemes, deny internal/metadata networks and redirects, and bound timeout/response bytes. PostgreSQL tools use allowlisted identifiers and parameterized values, read-only transactions and explicit projections; never arbitrary SQL. Webhooks require signature and replay checks when configured.

Use migrations for all schema changes. Maintain unit, integration, security, tenant, approval and Inspector tests. Run lint, typecheck, tests, build and relevant runtime checks; record what actually ran. Do not substitute runtime mocks for required functionality. External fixtures belong only in tests or the demo CRM. Do not commit credentials. Keep docs and .env.example current. No destructive operations or production publication without authorization.

V1.1 runtime connectors must run through the private process worker, including discovery and connection tests. Keep worker concurrency, job deadlines, hard cancellation and durable dispatch claims. Preserve trace IDs and safe failure classifications. Never automatically retry ambiguous writes or rotating OAuth refreshes. OAuth adapters are provider-neutral deployment modules; tokens and PKCE verifiers are encrypted, states single-use and tenant/principal bound. The current process boundary is for fault isolation, not untrusted-code sandboxing. Keep direct PostgREST management discovery disabled so it cannot bypass Gateway permissions. `db:migrate` must remain additive; only the explicitly named `db:reset` may reset local data.

V1.2 staging/production use the private authenticated HTTP Worker service; never publish its port. Preserve the child-process isolation and database claim behind that transport. Readiness checks dependencies; liveness does not certify provider access. OAuth providers may restrict connector IDs; Google credentials must never be attached to arbitrary OpenAPI/webhook endpoints. OTel attributes/events must use the metadata allowlist and never include URLs, payloads, credentials or exception text. Keep environment separation and fail-fast validation. Public HTTPS, cloud migrations and real OAuth consent require actual verification before claiming PASS; local fixtures do not prove a public deployment.
